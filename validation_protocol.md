# validation_protocol.md — Протокол самопроверки

Жёсткое правило: **агент не имеет права переходить к следующему пункту
бэклога, пока текущая задача не пройдёт весь применимый чек-лист ниже.**
Если какой-то пункт не пройден — задача считается незавершённой, независимо
от того, что говорит внутренняя оценка агента о качестве кода.

Это применимо к любому изменению в `blueos/`. Чек-лист для документации
(CLAUDE.md, docs/) короче — см. раздел «Документация» внизу.

## Чек-лист для изменений кода

Выполнять строго по порядку — каждый следующий шаг имеет смысл только если
предыдущий прошёл:

1. **`git status`** — прочитан и понятен весь diff, ничего постороннего не
   зацеплено (см. `.claudeignore` — если предлагается закоммитить что-то
   оттуда, это ошибка).
2. **Lint:** `ruff check blueos/ tests/` — 0 ошибок.
3. **Формат:** `ruff format --check blueos/ tests/` — без расхождений.
4. **Типизация:** `mypy blueos/ --strict --ignore-missing-imports` — 0 ошибок.
5. **Юнит-тесты (быстрые):** `pytest tests/ -m "not safety" --tb=short -q`
   — все зелёные.
6. **Safety-тесты** (только если менялся `safety_monitor.py` или что-то,
   что он импортирует): `pytest tests/test_safety_monitor.py -m safety -v`
   — все зелёные. **Никогда не пропускать этот шаг молча** — если
   safety-тест красный, работа останавливается, а не коммитится "как есть".
7. **Покрытие:** `pytest tests/ --cov=blueos --cov-report=term-missing`
   — общий процент не должен снижаться относительно зафиксированного в
   `state_journal.md`; целевой порог — см. CLAUDE.md (текущая цель: 99%+).
8. **Обновлён `state_journal.md`** — новая запись с результатом шагов 1–7.

Если шаг 2, 3 или 4 падает — задача не считается сделанной, даже если тесты
шага 5 зелёные (тесты могут проверять поведение, а не типы/стиль).

## Стоп-условия (см. Золотое правило в CLAUDE.md)

Если после трёх попыток исправить один и тот же провалившийся шаг агент не
может добиться зелёного результата — это повод остановиться и задать один
точный вопрос оператору, а не продолжать угадывать (см. «Правило 99» /
Золотой мета-хак в `docs/ai_autonomy_lifehacks.md`).

## Чек-лист для документации (CLAUDE.md, docs/*.md, *.json)

1. Файл синтаксически валиден (Markdown рендерится; JSON проходит
   `python -m json.tool <file> > /dev/null`).
2. Если менялись ключевые константы, упомянутые в CLAUDE.md
   («Key constants — do not change without updating README») — README.md
   и CLAUDE.md обновлены синхронно.
3. Если добавлен новый файл-протокол (по образцу `state_journal.md`,
   `validation_protocol.md`) — в CLAUDE.md добавлена на него ссылка в
   разделе «Autonomous Operation Protocol».

## Чек-лист перед сборкой контейнера (когда появится Dockerfile)

Пока в репозитории нет `Dockerfile` — этот раздел не применяется. Как только
он появится, здесь должен быть добавлен шаг вида
`docker build -t boreas-blueos:test .` и `docker run --rm boreas-blueos:test
pytest -m "not safety"` как обязательная часть протокола.
