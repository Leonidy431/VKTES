# state_journal.md — Журнал состояний автономной работы

Обязательный протокол: агент **обновляет этот файл в конце каждой итерации**
(после каждой законченной пачки правок, перед переходом к следующему пункту
бэклога). Цель — защита от «зацикливания» и галлюцинаций о собственном
прогрессе: вместо того чтобы полагаться на память в контексте диалога,
следующая сессия (или следующая итерация текущей) читает этот файл как
источник истины о том, где реально остановилась работа.

## Формат записи

Каждая запись — новый блок сверху (последняя итерация первая). Обязательные поля:

```
## [YYYY-MM-DD HH:MM] Итерация N

**Фаза:** <название фазы/этапа из бэклога>
**Выполнено:** <что именно сделано за эту итерацию, конкретно, файлы/функции>
**Валидация:** <прошёл ли validation_protocol.md — да/нет, что именно проверено>
**Нерешённые проблемы:** <известные баги, TODO, недостающие тесты>
**Следующий шаг:** <ровно один конкретный следующий шаг, не список>
```

Правила ведения:
- Не переписывать прошлые записи — только добавлять новые сверху.
- Если после чтения этого файла неясно, в каком состоянии репозиторий —
  это баг протокола, а не повод придумывать состояние. Сначала `git status`
  и `git log`, потом запись.
- Одна итерация = одна законченная, самодостаточная единица работы
  (не обязательно один коммит, но один проверяемый результат).

  `git fetch origin <branch> && git checkout -B <branch> origin/<branch>`.
- Проверено: `git ls-remote origin` показывает, что на удалённом репозитории
  существует **только** ветка `claude/write-boreas-readme-YYTjg` — нет
  `main`/`master`. `gh` CLI не установлен в этой среде. Значит, запрошенный
  пользователем «мерж» не может быть выполнен автоматически без уточнения:
  либо оператор указывает/создаёт целевую ветку, либо мерж делается вне этой
  сессии.
- Добавлены в CLAUDE.md два новых операционных правила (раздел
  «Development workflow»): (1) лимит 2 git push в день — работать пачками,
  прогонять validation_protocol.md один раз, потом пушить; (2) никогда не
  пушить/мержить при красном шаге протокола валидации.

**Валидация:** Полная — все шаги validation_protocol.md пройдены перед этой
записью (это единственное изменение в этой итерации — правки CLAUDE.md/

перепроверены для уверенности).

**Нерешённые проблемы:** См. `BACKLOG.md`. Дополнительно: запрос пользователя
на «мерж» блокирован отсутствием целевой ветки на remote — см. выше.

**Следующий шаг:** Дождаться от оператора уточнения целевой ветки для мержа
